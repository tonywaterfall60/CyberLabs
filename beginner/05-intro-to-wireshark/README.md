# Beginner 05 — Intro to Wireshark

**Difficulty:** Beginner  
**Estimated time:** 75–90 minutes  
**Prerequisites:** Beginner 03–04  
**Environment:** Wireshark + local traffic

## Why This Event Exists

Wireshark lets analysts see what systems are actually sending over a network. This event connects the networking concepts from Event 03 to real packets and prepares members for later packet-analysis and incident-response work.

## Learning Objectives

Members should be able to:

- explain what a packet capture is
- select an appropriate capture interface
- use basic display filters
- identify DNS, ICMP, TCP, and HTTP traffic
- recognize the TCP three-way handshake
- follow a simple conversation
- explain why packet analysis helps defenders

## Safety / Scope

Capture only traffic generated by your own machine or the provided local lab.

Do not capture or inspect other users' traffic without authorization.

## Wireshark Interface

Focus on three panes:

1. packet list
2. packet details
3. packet bytes

Important fields to locate:

- source
- destination
- protocol
- source/destination ports
- TCP flags
- DNS query name

## Guided Lab

### Task 1 — Start a Capture

Select the interface carrying your traffic and start capturing.

### Task 2 — Generate ICMP Traffic

```bash
ping 127.0.0.1
```

Filter:

```text
icmp
```

### Task 3 — Generate DNS Traffic

If Internet access is permitted:

```bash
nslookup example.com
```

Filter:

```text
dns
```

Identify the query name and response.

### Task 4 — Inspect TCP

Filter:

```text
tcp
```

Find a connection and identify:

```text
SYN
SYN-ACK
ACK
```

### Task 5 — Useful Filters

```text
dns
tcp
icmp
http
tcp.port == 80
ip.addr == 127.0.0.1
```

Discuss the difference between capture filters and display filters conceptually.

## Challenge

The challenge creates a local web service that generates safe traffic for analysis.

```bash
cd challenge
docker compose up -d
cat README.md
```

Use Wireshark while interacting with the local service.
