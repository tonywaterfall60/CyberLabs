# Beginner 05 — Intro to Wireshark

**Difficulty:** Beginner  
**Estimated time:** 75–90 minutes  
**Prerequisites:** Beginner 03–04  
**Environment:** Kali Linux, Wireshark, tshark, local traffic

## Why This Event Exists

Wireshark lets analysts see what systems are actually sending over a network. This event connects networking concepts to real packets and introduces both GUI and command-line packet analysis.

## Learning Objectives

Members should be able to:

- explain what a packet capture is
- select an appropriate capture interface
- use basic display filters
- identify DNS, ICMP, TCP, and HTTP traffic
- recognize the TCP three-way handshake
- follow a simple conversation
- use `tshark` for basic command-line packet inspection
- explain why packet analysis helps defenders

## Kali Tools Introduced

| Tool | Purpose |
|---|---|
| Wireshark | graphical packet analysis |
| tshark | command-line packet analysis |
| tcpdump | preview of command-line packet capture |

## Safety / Scope

Capture only traffic generated by your own machine or the provided local lab.

## Wireshark Interface

Focus on:

1. packet list
2. packet details
3. packet bytes

Important fields:

- source
- destination
- protocol
- ports
- TCP flags
- DNS query name

## Guided Lab

### Task 1 — Start a Capture

Select the interface carrying your lab traffic.

### Task 2 — Generate Traffic

```bash
ping -c 4 127.0.0.1
```

If permitted:

```bash
dig example.com
```

### Task 3 — Filters

```text
dns
tcp
icmp
http
tcp.flags.syn == 1
```

### Task 4 — TCP Handshake

Find:

```text
SYN
SYN-ACK
ACK
```

### Task 5 — Save a Capture

Save a small capture as:

```text
beginner.pcap
```

### Task 6 — Read It with tshark

```bash
tshark -r beginner.pcap
```

Show only DNS:

```bash
tshark -r beginner.pcap -Y dns
```

Show selected fields:

```bash
tshark   -r beginner.pcap   -T fields   -e frame.number   -e ip.src   -e ip.dst   -e _ws.col.Protocol
```

Discuss how the same evidence can be inspected in GUI and CLI workflows.

### Optional Preview — tcpdump

Show the command without requiring mastery:

```bash
sudo tcpdump -i lo
```

Explain that Intermediate Packet Analysis will use tcpdump more heavily.

## Beginner Packet-Analysis Workflow

Use this order:

~~~text
Capture the right interface
        ↓
Generate known traffic
        ↓
Filter to the conversation
        ↓
Identify request and response
        ↓
Follow one stream
        ↓
Save the PCAP
        ↓
Reproduce one observation with tshark
~~~

Knowing what traffic you generated makes the first packet-analysis experience easier to understand.

## Challenge

~~~bash
cd challenge
docker compose up -d
cat README.md
~~~

The expanded challenge includes a repeatable traffic generator:

~~~bash
./generate-traffic.sh
~~~

It creates a recognizable sequence:

~~~text
/
→ /status
→ /help
→ /status
~~~

Students then:

- identify TCP setup,
- inspect HTTP requests and responses,
- follow a TCP stream,
- save and hash the PCAP,
- reconstruct the request order,
- reproduce observations with tshark.
