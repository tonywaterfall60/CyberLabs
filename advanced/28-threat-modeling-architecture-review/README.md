# Advanced 28 — Threat Modeling / Architecture Review

## Event Snapshot

| Item | Details |
|---|---|
| Track | Advanced |
| Difficulty | Advanced |
| Estimated time | 90–120 minutes |
| Environment | Static/synthetic professional security evidence |
| Prerequisites | Professional Penetration-Test Reporting |

## Why This Event Exists

Security design review can prevent entire classes of vulnerabilities before code or infrastructure is deployed.

## Learning Objectives

- identify assets and trust boundaries
- map data flows
- write abuse cases
- connect threats to preventative and detective controls
- prioritize architecture changes before implementation

## Concepts

Emphasize evidence quality, decision-making, business/technical tradeoffs, limitations, and defensible communication.

## Guided Lab

The event lead should model one worked example, then require members to complete the remaining assessment independently.

## Challenge

[challenge/README.md](challenge/README.md)

## Expected Outcomes

Members should produce work that could be handed to another analyst, engineer, or stakeholder without relying on hidden context.

## Cleanup

No cleanup is required for these static/synthetic exercises.
